# 数学建模竞赛（国赛 CUMCM）

国赛是三天两夜的限时工程：一个队要在 72 小时内把一道开放题变成一篇 20 页以内、
自洽、可复现、评委看得懂的论文。决定名次的往往不是模型多高级，而是**能不能把做过的事
如实、清晰地讲出来**。这个技能就是围绕这一点组织的。

## 一、三条核心纪律

这三条比后面任何流程都重要。流程可以按情况裁剪，这三条不行。

### 1. 论文里的每一个数字，都必须来自真的跑过的代码

这是数模论文最致命也最常见的失败：模型讲得头头是道，"经计算，最优路径长度为 42.7 km"——
而这个 42.7 是编的。国赛附录要求提交完整可运行的源程序，**程序跑不出论文里的结果，
是可以取消评奖资格的**。更现实的是，评委见得多，编的数字通常自相矛盾：摘要说 42.7，
正文表格里是 43.1，图上看着像 40。

所以采用一条硬约定：**先算，再写**。

- 求解代码把所有要写进论文的量写进 `results/results.json`，键名要能读懂
  （`problem1.optimal_cost`、`problem2.rmse`、`problem3.sensitivity.alpha_range`）；
- 写论文时数字从这个文件里取，不从记忆里取；
- 写完用 `scripts/check_paper.py` 核对——它会把论文里出现、但 `results.json` 里找不到的
  数字标出来。标出来不一定是错（年份、题目给定的常数都会被标），但每一条你都要能说清来源。

如果某个量确实还没算出来，在正文里写 `【待计算：XXX】` 占位，不要先填一个像模像样的数。
占位符很显眼，编造的数字不显眼——这就是用占位符的全部理由。

### 2. 不利的结果照写

模型在某个场景下失效、灵敏度分析发现结论不稳、某个方法被实验证伪——这些**写出来是加分的**。
评阅要点里明写了"模型的合理性"和"结果的正确性"，一篇承认边界的论文比一篇处处最优的论文
可信得多，而且"模型评价与推广"这一节本来就是拿分点，没有缺点可写的队伍只能在那里凑套话。

具体做法：做完灵敏度分析，如果发现参数一动结论就翻，就在正文写清楚翻转的阈值在哪；
如果对比了三种方法而你选的那种不是全场最优，就写清楚它在哪类数据上让出了多少、
换回了什么。**不要因为结果不好看就换个说法**。

### 3. 摘要是评委看的第一样东西，也常常是唯一看完的东西

初评阶段评委看一篇论文的时间是分钟级的，摘要页决定了这篇论文进不进下一轮。
所以摘要**最后写**（因为要有结果才写得出），但要**写得最用力**。

一份能过关的摘要长这样：

- 每个子问题一段，顺序和正文一致；
- 每段结构固定：**针对什么问题 → 建立了什么模型 → 用什么方法求解 → 得到什么具体结果（带数字）**；
- 每段必须有至少一个具体数字结论。"通过模型求解得到了较优的方案"这种句子等于没写；
- 全文（含标题、关键词）不超过一页；关键词 4–6 个，写具体方法名不写"数学模型"这种废话。

反面例子：
> 本文针对问题一，建立了合理的数学模型，运用相关算法进行求解，得到了较好的结果。

正面例子：
> 针对问题一的产能分配，本文以总利润最大为目标、以设备工时与原料库存为约束，
> 建立混合整数线性规划模型，用分支定界法（Gurobi）求解，得到最优排产方案的
> 日利润为 18.63 万元，较题目给定的基准方案提升 12.4%；瓶颈落在 3 号设备，
> 其工时利用率达 99.2%。

## 二、工作流

按阶段推进。每个阶段结束时明确交付了什么，不要在没有产出的情况下滑到下一阶段。

### 阶段 0：拆题（预计 1–2 小时）

读完题目后先写一份 `notes/题目拆解.md`，回答四件事：

1. **题目一共问了几个问题，每个问题要求交付什么**（一个数？一张表？一个方案？一段论证？）。
   逐条列出来。国赛丢分最冤的方式是漏答一小问。
2. **每个问题的输入是什么**——题目给的数据、附件、常数，还有哪些量需要自己假设或估计。
3. **问题之间的依赖**：问题二是不是要用问题一的结果？如果是，问题一的输出格式就被约束了。
4. **这是哪一类问题**：优化 / 评价 / 预测 / 机理分析 / 统计推断，还是几类的组合。
   这一步直接决定选型，判断依据见 `references/模型选型.md`。

如果用户在选题（A/B/C 之间犹豫），把这份拆解对每道题各做一遍再比较，别凭题面感觉选。

### 阶段 1：数据勘察与假设（预计 2–4 小时）

**先看数据再建模。** 拿到附件数据后，第一件事是跑一遍探查：规模、缺失、量纲、
异常值、时间跨度、分布形态、变量间相关性。很多"精妙"的模型是在对数据一无所知的
情况下想出来的，跑起来才发现数据根本不支持。

数据探查脚本存 `code/explore_data.py`，图存 `figures/`。

然后写模型假设。**假设要是承重的**——每一条都应该在后面某处被用到。
写完假设自查：这条假设如果去掉，我的推导哪一步会垮？答不上来的，删掉。

好的假设会说明"为什么这样假设是合理的"，而不只是"假设 XX 服从正态分布"。

### 阶段 2：建模（每个子问题 2–4 小时）

先读 `references/模型选型.md` 确定候选模型族，然后：

- **写清楚符号**：符号说明表放正文靠前的位置，后面全文统一，不要同一个量换两个符号；
- **模型要有推导**，不是把公式抄下来。目标函数怎么来的、约束对应现实中的什么限制，
  要说清楚。评阅要点里"建模的创新性"很大程度上体现在这里；
- **一个子问题可以有基础模型 + 改进模型**，先给出能跑通的基础版，再说明改进动机。
  这比一步到位给一个复杂模型更容易讲清楚，也更容易在时间不够时降级交付。

不要反射性地上层次分析法、熵权法、灰色预测。这三样被用滥了，评委一看就知道套模板。
用它们要有理由；`references/模型选型.md` 里写了它们各自真正适用和不适用的场合。

### 阶段 3：求解与检验（每个子问题 2–5 小时）

代码放 `code/`，一个子问题一个文件（`solve_p1.py`）。运行入口要能一键复现——
附录要提交完整可运行的源程序，评委真的会试着跑。

求解完成后**必须做检验**，至少一项：

- 优化问题：解的可行性验证（把解代回所有约束逐条检查）、与基准/贪心解对比、对偶间隙或收敛曲线；
- 预测问题：留出集或交叉验证的误差，不要只报训练集拟合优度；
- 评价问题：与已知排序或专家判断对照、评价结果对权重扰动的稳定性；
- 机理模型：量纲一致性、极限情形（参数取 0 或 ∞ 时模型退化成什么）、守恒量是否守恒。

检验的具体做法见 `references/求解与检验.md`。

**出图用 `scripts/setup_cn_plot.py`**——它解决 matplotlib 中文字体乱码（这个坑每年
浪费掉大量队伍的时间），并统一配色字号，让全文的图看起来像一套。

所有结果写入 `results/results.json`。

### 阶段 4：灵敏度分析与模型评价（2–3 小时）

这两节是明确的拿分点，而且是很多队伍草草带过的地方。

**灵敏度分析**要有具体对象：挑 2–4 个你最不确定的参数（自己估的、文献取的、
题目没给死的），扫描它们，看结论怎么变。产出应该是一句可检验的话：
"当运输成本系数在 ±30% 内变化时，最优路径选择保持不变；超过 +45% 后
方案切换为 B 路线"——而不是"模型具有较好的鲁棒性"。

**模型评价**要真的写缺点。写不出缺点说明灵敏度分析没做到位。

### 阶段 5：论文写作（8–12 小时）

用 `assets/论文模板.md` 作骨架。写作顺序建议：正文各问 → 模型评价 → 参考文献 →
**最后写摘要**。

格式规范逐条见 `references/论文格式与评阅.md`。写完跑一次：

```bash
python scripts/check_paper.py 论文.md --results results/results.json
```

它检查身份信息泄漏、摘要长度、页数估算、附录代码、参考文献引用闭合、数字溯源。
这些都是机械规则，交给脚本比人工核对可靠——把规范变成机制，而不是变成一条要记住的纪律。

## 四、常见失分点速查

写完对照一遍：

- [ ] 有小问漏答（对照阶段 0 的拆解逐条勾）
- [ ] 摘要没有具体数字，或超过一页
- [ ] 正文出现学校名、姓名、学号，或者加了页眉——这是**资格问题**，不是扣分问题
- [ ] 正文放了目录（国赛正文不要目录）
- [ ] 附录没有完整可运行代码，或代码跑不出论文里的结果
- [ ] 图没有中文标签 / 坐标轴没单位 / 图题在图上方（图题应在图下方，表题在表上方）
- [ ] 参考文献编号在正文里没被引用，或正文引用了不存在的编号
- [ ] 只报了训练集拟合优度，没有任何独立检验
- [ ] 灵敏度分析写成"鲁棒性较好"一句话
- [ ] 模型评价里的"缺点"其实是变相的优点（"模型考虑因素较多，计算量偏大"）
- [ ] 正文超过 20 页（尽量控制在 20 页以内，把代码和长表挪去附录）

## 五、时间不够时的降级顺序

72 小时经常不够。如果必须砍，按这个顺序砍，理由是保住评分权重最高的部分：

1. 先砍**改进模型**，保住基础模型跑通并写完整——一个讲清楚的简单模型远胜一个没跑完的复杂模型；
2. 再砍**图的数量**，保住每问至少一张关键结果图；
3. 再砍**正文的文献综述**，保住假设、建模、求解、检验四段；
4. **绝不砍**：摘要、任何一个子问题的作答、附录代码、结果的真实性。

最后一条尤其：宁可在正文里写"由于时间限制，问题四仅给出建模思路，未完成数值求解"，
也不要填一个编造的结果。前者扣的是那一问的分，后者扣的是整篇论文的可信度。
