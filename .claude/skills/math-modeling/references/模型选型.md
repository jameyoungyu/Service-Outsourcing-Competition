## 一、先判断题型

看题目问的是什么，而不是看题目属于哪个行业。

| 题目在问 | 题型 | 典型信号词 |
|---|---|---|
| 怎么安排最好 / 最少花多少 / 最多能做到多少 | **优化** | 最优、最小、最大、方案、调度、选址、分配、路径 |
| 哪个更好 / 打多少分 / 排个序 | **评价** | 评价、评估、排序、指标体系、综合得分 |
| 明年会怎样 / 这个值是多少 | **预测** | 预测、估计、推断、趋势、未来 |
| 为什么会这样 / 这个过程怎么运作 | **机理分析** | 建立…的数学模型描述、解释、机理、演化 |
| 这个因素有没有影响 / 影响多大 | **统计推断** | 显著性、相关性、影响因素、是否有关 |

**大多数国赛题是组合的。** 常见组合：

- 第一问统计分析摸清数据 → 第二问建预测模型 → 第三问用预测结果做优化（C 题高频）；
- 第一问机理建模 → 第二问参数辨识 → 第三问基于模型做优化（A 题高频）；
- 第一问建评价体系 → 第二问用评价结果排序/分类 → 第三问给改进建议（B/E 题常见）。

识别出组合结构很重要，因为**前一问的输出格式被后一问的输入需求约束**。
如果第三问要做优化、需要每个方案的成本，第二问的预测就必须输出点估计
（还最好带区间），而不是只输出一个分类标签。

## 二、优化类

### 选型判断树

先问三个问题，答案唯一确定模型族：

1. **决策变量是连续还是离散？**（能不能取 3.7 个）
2. **目标和约束是不是线性的？**
3. **有几个目标？有没有不确定性？**

| 变量 | 目标/约束 | 模型 | 求解 |
|---|---|---|---|
| 连续 | 线性 | 线性规划 LP | `scipy.optimize.linprog`、PuLP |
| 整数/0-1 | 线性 | 整数规划 IP / 混合整数 MILP | PuLP + CBC、Gurobi（有学术许可） |
| 连续 | 非线性凸 | 凸优化 | `cvxpy` |
| 连续 | 非线性非凸 | NLP | `scipy.optimize.minimize`(SLSQP/trust-constr) |
| 离散、组合爆炸 | — | 启发式/元启发式 | 遗传算法、模拟退火、蚁群、禁忌搜索 |
| 分阶段决策 | — | 动态规划 | 自己写状态转移 |
| 网络结构 | — | 图论算法 | `networkx`（最短路、最大流、最小生成树、匹配） |

### 关键提醒

**能用精确求解就不要用启发式。** 每年都有队伍对着一个 200 变量的线性问题上遗传算法。
MILP 求解器几秒钟给全局最优并附带最优性证明（gap），遗传算法给一个说不清好坏的解，
还要额外花篇幅解释参数怎么调的。**先试 MILP，跑不动再上启发式**，并且要说明为什么跑不动
（变量规模、求解超时时间），这个说明本身就是论文里有价值的内容。

**用了启发式，必须有对照。** 一个遗传算法的解，如果没有和贪心解、随机解、
或小规模上的精确最优解对比，读者无法判断它好不好。小规模实例上跑精确解做对照，
是最有说服力的做法。

**多目标不要直接加权求和了事。** 加权求和把"怎么权衡"这个真问题掩盖成一组拍脑袋的权重。
更好的做法是求 Pareto 前沿（`pymoo` 的 NSGA-II），把权衡关系画出来，
再说明在哪个点上取舍以及为什么。如果确实要加权，权重的来源必须交代，
并且要做权重的灵敏度分析。

**带不确定性的优化**：如果题目给了概率分布，考虑随机规划（场景法）或鲁棒优化，
而不是把随机量换成均值——用均值代替随机量会系统性高估性能（Jensen 不等式），
这个坑值得在论文里点明。

### 常见陷阱

- 约束写漏了导致解不可行却看不出来 → 求解后把解代回**每一条**约束逐条验证；
- 单位不统一（万元 vs 元，小时 vs 分钟）→ 建模时就在符号说明表里写死单位；
- 整数变量当连续变量解完再四舍五入 → 四舍五入后往往不可行，也不是最优。

## 三、评价类

评价题的核心难点不是算分，是**说清楚为什么这样算分是合理的**。

### 指标体系

先搭指标体系，再选赋权法。指标要满足：

- **可测**：数据拿得到（题目附件里有，或能从中算出来）；
- **不冗余**：高度相关的指标合并或删除，否则等于给某个维度偷偷加权。
  做法：算指标间相关系数矩阵，`|r| > 0.8` 的对要处理；
- **方向一致**：正向/负向指标统一（负向指标取倒数或用极差法反向归一化）。

归一化方法要写清楚用了哪种（min-max、Z-score、向量归一化），
因为不同归一化会改变结果，这是评委会追的细节。

### 赋权法对照

| 方法 | 权重来自 | 适用 | 不适用 |
|---|---|---|---|
| 层次分析法 AHP | 人的主观判断 | 有明确专家意见或题目给了偏好 | 你自己随便填判断矩阵（最常见的滥用） |
| 熵权法 | 数据的离散程度 | 纯客观、指标数据完整 | 指标本身有明确重要性差异时（熵权法会给"大家都差不多"的重要指标极低权重） |
| CRITIC | 对比强度 + 冲突性 | 指标间有相关性时比熵权法好 | 样本太少 |
| 主成分分析 PCA | 方差贡献 | 降维 + 综合评价，指标多且相关 | 主成分没有可解释含义时，评价结果讲不清楚 |
| TOPSIS | 到理想解的距离 | 排序（要配合某种赋权） | 单独用——TOPSIS 是排序方法不是赋权方法 |
| 组合赋权 | 主客观加权融合 | 想兼顾两者 | 融合系数又是拍脑袋定的时候 |

**推荐做法**：主观法 + 客观法各做一次，比较两组排序的差异（用 Spearman 秩相关），
差异大的对象单独讨论为什么。这既避免了单一方法的武断，又天然产出了灵敏度分析的素材。

### 检验

评价模型最容易变成"算出来一堆分数，没人知道对不对"。至少做一项：

- 与题目给的已知结论/常识排序对照（如果有）；
- 权重扰动实验：权重各 ±20% 随机扰动 1000 次，看排序前三名的稳定率；
- 剔除单个指标看排序变化，识别哪个指标在主导结果。

## 四、预测类

### 按数据形态选

| 数据形态 | 首选 | 备选 |
|---|---|---|
| 单变量时间序列，有趋势/季节 | ARIMA / SARIMA、指数平滑 | Prophet |
| 多变量时间序列 | VAR、带外生变量的 ARIMAX | LSTM（数据量够才考虑） |
| 截面数据，特征多 | 梯度提升树（XGBoost/LightGBM） | 随机森林、线性回归（要可解释时） |
| 样本极少（< 20 点） | 灰色预测 GM(1,1)、简单回归 | 别上机器学习 |
| 有明确机理 | 机理模型 + 参数拟合 | 见第五节 |
| 分类/判别 | 逻辑回归、SVM、树模型 | 判别分析 |

### 关键提醒

**小样本不要上神经网络。** 国赛数据经常只有几十上百个样本。在这个规模上，
LSTM 打不过 ARIMA，深度学习打不过梯度提升树，而且你没有足够数据做可信的验证。
用了复杂模型却报不出可信的泛化误差，是纯粹的失分。

**必须报独立验证误差。** 只报 R² 或训练集 RMSE 等于没报。做法：

- 时间序列：按时间切分，**不能随机切分**（会造成未来信息泄漏）；
- 截面数据：K 折交叉验证，报均值 ± 标准差；
- 报多个指标：RMSE（量纲同原数据）、MAPE（相对误差，便于跨量级比较）、R²。

**预测要给不确定性。** 一个点预测"2026 年销量 3.2 万件"和一个区间预测
"3.2 万件（95% 区间 2.7–3.8）"，后者在论文里的分量完全不同，也更诚实。
ARIMA 自带区间；树模型可以用分位数回归或 bootstrap。

**外推要谨慎并写明。** 模型在训练数据范围外的表现是没有保证的。
如果题目要求预测 10 年后而数据只有 5 年，这个局限必须在"模型评价"里写出来。

## 五、机理分析类

A 题高频。特征是题目描述一个物理/化学/生物过程，要你"建立数学模型描述该过程"。

### 常用工具

- **常微分方程组**：随时间演化的状态量（传染病 SIR、种群、化学反应动力学、
  电路、力学系统）。求解用 `scipy.integrate.solve_ivp`；
- **偏微分方程**：还随空间变化（扩散、传热、波动）。有限差分法自己写，
  或 `fipy`；很多情况下可以先降维成 ODE；
- **元胞自动机 / 基于主体的仿真**：个体规则简单但整体行为复杂（交通流、人群疏散、
  森林火灾蔓延）；
- **几何/运动学建模**：涉及位置、角度、轨迹的（这类题 A 题特别多），
  先把坐标系和符号定义清楚，剩下的是解析几何 + 数值求根。

### 关键提醒

**量纲检查是免费的正确性验证。** 每个方程两边量纲必须一致。
量纲不一致的方程一定是错的，而且这个检查花不了两分钟。

**极限情形检验。** 参数取 0、取无穷、取对称值时，模型应该退化成已知的简单情形。
比如传热模型在导热系数趋于无穷时应该给出瞬时均温。做这个检验并写进论文，
比多画三张图有价值。

**参数辨识要说明来源。** 机理模型里的参数从哪来：题目给的、文献查的、
数据拟合的，三种要分别标注。拟合得到的参数要报置信区间或拟合优度。
如果参数是"取经验值"，这个参数就是灵敏度分析的头号对象。

**数值求解要验证收敛。** 步长减半后结果基本不变，才说明数值解可信。
这一条经常被跳过，但它是数值模型唯一的自证方式。

## 六、统计推断与因果

题目问"XX 是否影响 YY""哪些因素是主要因素"时用。

- **相关性**：Pearson（线性、连续）、Spearman（单调、有序）、
  卡方检验（类别变量）。相关不等于因果，论文里措辞要克制；
- **组间差异**：t 检验（两组）、方差分析 ANOVA（多组）、
  非参数替代（Mann-Whitney、Kruskal-Wallis，样本不正态时）；
- **多因素影响**：多元回归，报系数、标准误、p 值、VIF（多重共线性）。
  **VIF > 10 的变量要处理**，否则系数符号可能完全反过来；
- **降维/分组**：PCA、因子分析、聚类（K-means 要说明 K 怎么定的，
  用肘部法或轮廓系数，不要拍脑袋）。

**检验前先看假设是否成立**（正态性、方差齐性、独立性）。
在明显不满足正态的数据上跑 t 检验然后报 p 值，是评委一眼能看出的错误。

## 七、被用滥的三件套：慎用清单

层次分析法、熵权法、灰色预测 GM(1,1) 是国赛论文里出现频率最高的三个方法，
也是最容易让论文看起来像模板的三个方法。它们不是坏方法，但要用对地方。

**层次分析法 AHP**
- 真正适用：题目明确给了专家意见/偏好排序，或评价维度确实只能靠人判断；
- 滥用形态：自己编一个判断矩阵，凑到 CR < 0.1，然后声称权重"具有合理性"。
  评委知道那个矩阵是凑的；
- 如果要用：判断矩阵的每个数字要有依据（文献、题目描述、可解释的现实理由），
  并且做权重灵敏度分析。

**熵权法**
- 真正适用：纯客观赋权，指标数据完整且各指标本身重要性没有先验差异；
- 滥用形态：忽略一个事实——熵权法给"所有对象取值都差不多"的指标极低权重，
  但这类指标可能恰恰是最重要的（比如安全性指标，大家都达标不代表它不重要）；
- 如果要用：检查一下算出的权重是否违反常识，违反了就说明这个场景不适合纯客观赋权。

**灰色预测 GM(1,1)**
- 真正适用：数据点极少（4–20 个）、近似指数增长、短期外推；
- 滥用形态：数据有几百个点还用 GM(1,1)，或者数据明显不是指数趋势还硬套；
- 如果要用：必须做级比检验（判断数据是否适合建 GM 模型）和后验差检验，
  并且和一个简单基线（线性回归、移动平均）对比。

**通用建议**：如果这三个方法之一是你的主模型，问自己一句
"换成别的方法结果会怎样"，并且真的去试一下。做了对比的论文，
即使最后还是用了这三个方法之一，说服力也完全不同。

## 八、创新点从哪里来

评阅要点里有"建模的创新性"。创新不是发明新算法，实际可行的来源有这几种：

1. **建模角度的转换**：别人按题目字面建模，你识别出问题的等价形式
   （比如把一个看起来复杂的排程问题识别成经典的图着色或装箱问题），
   从而能用成熟算法且有理论保证；
2. **约束的精细化**：把题目里含糊的现实限制（"考虑实际可行性"）
   显式写成数学约束，并说明依据；
3. **方法的组合**：用 A 方法的输出做 B 方法的输入，且说明为什么这个组合
   解决了单用任一方法的缺陷；
4. **对方法失效边界的刻画**：做实验找出你的模型在什么条件下失效，
   并给出判据。这是最容易被忽略、但含金量很高的一类创新——
   它证明你真的理解自己的模型，而不是碰巧调通了；
5. **可解释性的增强**：给出模型结论的敏感因子分解、贡献度归因，
   让结果能指导决策而不只是给个数。

**创新点要在摘要里点名**，并在正文对应位置有独立小节。
藏在正文里没人找得到的创新等于没有。
