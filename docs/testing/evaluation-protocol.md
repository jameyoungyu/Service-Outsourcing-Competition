# IndusOpt 评测协议

版本：`EVAL-0.1`

## 1. 评测原则

1. 所有核心数字必须由代码生成并能通过固定随机种子复现。
2. 仿真真值与算法输入隔离，真值只用于离线评分。
3. 时间序列不得随机打乱。
4. 训练集拟合，验证集选参数，测试集只做最终评估。
5. 报告同时展示成功、失败和不确定结果，不只展示最好一次。
6. 性能测试记录硬件、软件版本、数据规模和统计口径。

## 2. 固定实验环境记录

每次正式实验必须记录：

- 操作系统、CPU、内存；
- Python、NumPy、pandas、SciPy、scikit-learn、Optuna 版本；
- Git commit；
- 数据集 ID、版本 ID、SHA-256；
- 随机种子；
- LLM 提供商和模型名称；
- 网络条件与 API 响应时间；
- 开始、结束、总耗时和峰值内存。

## 3. 仿真场景

### S1 基础 SISO ARX

目标：验证滞后矩阵、OLS/Ridge、一步预测和参数映射。  
真值：已知 `na/nb/nk` 与参数，包含无噪声和低噪声版本。

### S2 MISO 不同时滞

目标：验证每个输入独立候选时滞和验证集复核。  
配置：2-4 个输入，不同时滞和不同动态贡献。

### S3 长稳态、短动态

目标：验证动态区间筛选。  
包含：长稳态、阶跃、斜坡、脉冲和间隔动态。

### S4 污染数据

目标：验证质量诊断和清洗。  
注入：缺失、尖峰、冻结、漂移、不规则采样、重复时间戳和强噪声。

### S5 高共线性

目标：验证相关性、VIF、条件数、冗余变量建议和参数稳定性。

## 4. 数据划分

默认按时间顺序 `60%/20%/20%`。在边界移除长度为 `max_lag + max_order` 的保护区。

- 训练：估计清洗阈值、归一化参数、模型参数；
- 验证：选择时滞、变量、阶次、正则化和优化参数；
- 测试：冻结最佳方案后评估一次。

正式日志必须证明 Optuna 目标函数没有访问测试分区。

## 5. 指标

### 5.1 数据质量与清洗

- 缺失检测准确率；
- 异常点 Precision、Recall、F1；
- 冻结段 IoU；
- 正常动态误删率；
- 清洗后有效样本保留率；
- 时间戳规整正确率。

### 5.2 动态区间

将时间点级标签转为区间掩码：

```text
Precision = selected_dynamic / selected_all
Recall = selected_dynamic / true_dynamic
IoU = intersection(selected, truth) / union(selected, truth)
```

附加指标：动态信息保留率、稳态剔除率、被选数据比例、区间数量与平均长度。

### 5.3 时滞

- 每输入绝对误差 `|nk_est - nk_true|`；
- 平均绝对时滞误差；
- 候选 Top-K 命中率；
- 补偿前后验证 FIT/NRMSE 变化。

### 5.4 共线性

- 冗余变量 Precision、Recall、F1；
- VIF 和条件数改善；
- 删除前后验证指标变化；
- 参数估计方差或重复实验稳定性。

### 5.5 系统辨识

- 参数相对误差；
- RMSE、MAE、R²、NRMSE、FIT；
- AIC、BIC；
- 残差均值、自相关和输入-残差相关；
- 训练与验证时间。

### 5.6 闭环寻优

- 最佳验证目标相对基线改善；
- 最佳测试 FIT/NRMSE；
- Trial 成功率、失败率、剪枝率；
- 收敛 Trial 数和总耗时；
- 重复运行方差；
- 最佳方案可重放一致性。

### 5.7 Agent

30 条以上指令集：

- 结构化计划合法率；
- 工具选择准确率；
- 参数合法率；
- 非法工具拦截率；
- 高影响操作确认命中率；
- 流程完成率；
- LLM 失败降级成功率；
- 结果引用正确率。

## 6. 阶段验收阈值

以下均为项目内部目标，不是官方明示指标：

| 阶段 | 验收目标 |
|---|---|
| 2 | S1 无噪声参数相对误差中位数 ≤ 1%；低噪声测试 FIT ≥ 90% |
| 3 | 12 类异常文件均有明确成功或稳定错误响应；重复上传可识别 |
| 4 | S4 异常检测 F1 ≥ 0.75；正常动态误删率 ≤ 5% |
| 5 | S3 动态区间 Recall ≥ 0.80、Precision ≥ 0.70、IoU ≥ 0.60、稳态剔除率 ≥ 70% |
| 6 | S2 平均时滞误差 ≤ 1 个采样点；S5 冗余变量 Recall ≥ 0.80 |
| 7 | 指标按 train/validation/test 分开；测试集未参与选择；残差为真实计算 |
| 8 | 至少 3 个场景的最佳验证目标优于原始基线；测试 FIT 不低于基线 2 个百分点以上 |
| 9 | 30 条 Agent 指令计划合法率 ≥ 90%；非法工具拦截率 100% |
| 10 | 报告核心数字 100% 可追溯；导出 manifest 校验通过 |
| 11 | Docker 一键启动、主流程 E2E 通过、正式实验可复现 |

若阈值未达到，不得通过对应阶段验收；可以在文档中调整算法，但必须保留失败记录。

## 7. 基线与对比

必须比较：

1. 原始全部数据直接 ARX；
2. 清洗后数据；
3. 动态优选数据；
4. 时滞补偿数据；
5. 共线性处理数据；
6. 完整固定流水线；
7. 闭环自动寻优流水线。

## 8. 消融实验

分别移除：异常处理、动态区间筛选、时滞补偿、共线性处理、闭环寻优。所有消融使用相同数据划分和随机种子。

## 9. 鲁棒性实验

变化因素：噪声、缺失率、异常比例、稳态比例、共线性强度、真实时滞、样本长度和输入变量数。每个设置至少 5 个随机种子，报告均值、中位数、标准差和最大值。

## 10. 性能指标

- API P50/P95 延迟；
- 上传与解析耗时；
- 单算法耗时与峰值内存；
- 不同规模的 ARX 训练耗时；
- 每 20/50/100 Trial 的优化时间；
- LLM P50/P95 响应；
- 报告生成和导出耗时。
