# 阶段 0 范围与口径冻结

冻结编号：`SF-0.1`  
状态：候选冻结，待开发者确认  
冻结日期：2026-07-27

## 1. 产品定义

IndusOpt 是面向流程工业建模工程师的本地化 Web 系统。它通过自然语言生成受约束的算法工作流，对多变量时序数据进行规整、清洗、动态区间筛选、时滞补偿、共线性处理、ARX 辨识和闭环寻优，最终交付可复现的数据版本、模型、指标和报告。

它不是通用数据分析平台，也不是让大模型自由编写并执行 Python 的代码智能体。

## 2. 第一版系统边界

### 2.1 支持的工业对象

| 项目 | 冻结决定 | 类型 |
|---|---|---|
| 时间域 | 离散时间 | 自加约束 |
| 输入输出结构 | 多输入单输出 MISO | 自加约束 |
| 输入变量数 | 1-8 个过程输入 | 自加约束，可配置上限 |
| 输出变量数 | 恰好 1 个目标输出 | 自加约束 |
| 模型 | 线性 ARX | 自加约束 |
| 参数估计 | 普通最小二乘、岭回归 | 自加实现 |
| 数据来源 | 自研仿真为主，用户 CSV 和公开数据为辅 | 项目决定 |
| 运行环境 | 普通 CPU 电脑，无 GPU 依赖 | 与官方普通环境目标一致 |

### 2.2 CSV 输入口径

第一版 CSV 必须满足：

- 首行包含唯一列名；
- 恰好选择一列时间戳；
- 至少选择一个输入列和一个输出列；
- 输入、输出列可转换为数值；
- 时间戳可解析，或由用户明确指定解析格式；
- 同一列不能同时作为输入和输出；
- 原始文件只读保存，任何处理均生成新版本。

默认工程限制属于可配置值，不属于官方指标：

- 默认单文件上限：50 MiB；
- 推荐演示规模：10,000-100,000 行、2-8 个输入变量；
- 最低可建模样本量：`max(200, 20 × 模型参数数)`；
- 时间有时区时统一存为 UTC；无时区时按“数据集本地时间”解释并记录声明。

### 2.3 数据版本与血缘

- 原始版本记为 `RAW`，不可覆盖、不可原地修改。
- 每个处理步骤创建新的不可变数据版本。
- 数据版本保存父版本、操作类型、参数、代码版本、随机种子、时间范围、行列变化和校验和。
- 多步骤流水线形成有向无环血缘图。
- 回滚不是覆盖数据，而是将某个历史版本重新设为后续输入。
- 删除采用逻辑删除；原始文件的物理清理必须由管理员显式执行，并保留日志。

## 3. 数据划分与防泄漏口径

### 3.1 默认划分

按时间顺序划分：

- 训练集：前 60%；
- 验证集：中间 20%；
- 测试集：最后 20%。

比例可配置，但不得随机打乱。

### 3.2 边界隔离

- 在分区边界设置保护间隔，长度至少为当前候选最大时滞与最大模型阶次之和。
- 标准化、异常阈值、平滑参数和其他需要拟合的数据变换只使用训练集估计。
- 候选时滞、变量集合、模型阶次和闭环参数只根据训练集与验证集选择。
- 测试集只在最终方案冻结后评估一次，不参与 Trial 目标函数。
- 仿真真值只用于评测，不传递给优化器或 Agent。

## 4. 第一版算法范围

### 4.1 P0 必做

- CSV 校验、解析、时间排序与重复时间戳处理；
- 固定周期重采样与受限插值；
- 缺失、尖峰、冻结值和基础漂移诊断；
- Hampel、IQR、Z-score 中至少三种规则方法；
- 滑动窗口动态区间识别与可解释质量评分；
- 互相关候选时滞 + 验证集 ARX 复核；
- Pearson、Spearman、VIF、条件数；
- 冗余变量删除建议与用户确认；
- MISO ARX、OLS、Ridge、一步预测；
- RMSE、MAE、R²、NRMSE、FIT、AIC、BIC；
- Optuna TPE 多参数闭环寻优；
- Agent 白名单工作流；
- 报告和 CSV/JSON 导出。

### 4.2 P1 争取实现

- Isolation Forest；
- Savitzky-Golay 平滑；
- 自由仿真；
- 残差自相关与输入-残差互相关；
- 任务暂停、恢复和 Trial 参数重要性；
- HTML/PDF 报告与 SVG 图表。

### 4.3 第一版明确不做

- 完整 MIMO；
- 非线性系统辨识；
- LSTM、Transformer、神经状态空间模型；
- 实时流、PLC、OPC UA；
- 数字孪生、故障诊断、预测预警；
- PCA、PLS、Lasso 作为正式主流程；
- 任意 Python、Shell、SQL 执行；
- 多租户与复杂组织权限；
- 移动端 App；
- 云端分布式计算；
- 复杂可视化报告编辑器。

## 5. Agent 权限冻结

### 5.1 白名单工具

```text
profile_dataset
align_and_resample
detect_anomalies
clean_data
detect_dynamic_segments
estimate_delays
analyze_collinearity
select_variables
fit_arx
evaluate_model
optimize_pipeline
generate_report
export_dataset
```

### 5.2 Agent 可以做

- 识别用户目标、数据集和约束；
- 选择白名单工具并填写合法参数；
- 根据工具结果决定继续、停止或请求确认；
- 对真实算法输出做工程化解释；
- 生成结构化计划和报告草稿。

### 5.3 Agent 禁止做

- 伪造任何数值、图表、数据版本或模型结果；
- 执行任意 Python、Shell、SQL 或系统命令；
- 绕过 Pydantic 参数校验；
- 修改原始数据；
- 使用测试集进行调参；
- 自动删除原始文件；
- 在高影响变量删除、覆盖导出、长任务启动前绕过人工确认；
- 把互相关最大峰直接当成最终时滞；
- 隐藏失败 Trial 或失败工具调用。

## 6. 技术栈冻结

| 层 | 第一版决定 |

| 前端 | Vue 3 + Vite + TypeScript + Element Plus + ECharts |
| API | FastAPI + Pydantic 2 |

## 7. 角色与权限

MVP 采用单租户、本地工作区模式，官方核心流程不依赖登录。

- **建模工程师**：执行所有核心业务流程。
- **评审/演示观察者**：只读查看运行、图表和报告，P1。
- **系统管理员**：仅用于配置 LLM、文件限制和清理策略，P1。

阶段 0 不要求 Gemini 设计完整登录与权限系统；登录页从 MVP 信息架构中移除。后续如增加身份认证，不得影响核心演示链路。

## 8. 异常与失败口径

| 场景 | 处理原则 |
|---|---|
| CSV 无法解析 | 保留原文件和失败记录，不创建可用数据版本 |
| 样本不足 | 阻止建模，返回所需最低样本量和当前样本量 |
| 时间戳异常 | 生成诊断，要求用户选择处理策略 |
| 长缺失段 | 默认不插值，标记不可用区间 |
| 算法参数越界 | 在执行前拒绝 |
| 长任务失败 | 记录已完成步骤和失败原因，可从最近稳定版本重试 |
| LLM 不可用 | 允许用户使用手工配置工作流，核心算法仍可运行 |
| 报告生成失败 | 不影响数据和模型结果，报告任务可独立重试 |

## 9. 回滚策略

- 需求文档回滚：通过 Git 恢复前一标签。
- 数据处理回滚：选择父数据版本重新运行，不删除新版本。
- 模型回滚：将上一模型版本标记为 active，不覆盖参数。
- 优化回滚：停止 Study，保留全部 Trial，恢复基线方案。
- Agent 回滚：废弃当前计划，保留审计记录，重新生成计划。
- 任务队列回滚：标记任务失败或取消，不直接修改已经产出的稳定版本。
