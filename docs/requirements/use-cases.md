# IndusOpt 核心用例

版本：`UC-0.1`

## 1. 参与者

| 参与者 | 说明 |
|---|---|
| 建模工程师 | 核心用户，上传数据、配置变量、运行算法、确认建议、导出结果 |
| Agent | 生成并控制受约束工作流，不直接计算指标 |
| 后台 Worker | 执行耗时算法与报告任务 |
| 评审/观察者 | 查看运行证据、模型指标和报告，第一版为只读可选角色 |
| 外部 LLM 服务 | 提供意图解析与自然语言解释，核心数值计算不依赖其生成 |

## 3. 详细用例

### UC-01 生成仿真数据集

**前置条件**：系统可用，用户进入仿真数据页面。  
**主流程**：选择场景 → 配置样本数、噪声、时滞、随机种子 → 创建任务 → Worker 生成 CSV 和真值 JSON → 系统校验一致性 → 注册为数据集。  
**异常**：参数不稳定、模型发散、生成中断时，不注册可用数据集并保留失败原因。  
**后置条件**：产生不可变原始版本和独立真值文件；真值文件不对优化器开放。

### UC-02 上传并解析 CSV

**前置条件**：用户拥有合法 CSV。  
**主流程**：上传 → 扩展名/MIME/大小校验 → SHA-256 → 编码和分隔符检测 → 表头预览 → 暂存。  
**异常**：重复上传返回现有数据集提示；解析失败不创建可用版本。  
**后置条件**：原文件只读保存，生成待配置数据集记录。

### UC-03 配置字段

**主流程**：选择时间列 → 选择 1-8 个输入列 → 选择一个输出列 → 指定时间格式与单位 → 后端验证 → 创建 RAW 数据版本。  
**异常**：列重复、非数值、输出与输入冲突、时间戳无法解析、样本不足。  
**后置条件**：数据集进入 `READY_FOR_PROFILE`。

### UC-04 数据质量诊断

**主流程**：运行 profile → 计算行列数、时间范围、采样间隔、缺失、重复、常量、冻结、分位数和相关性 → 生成质量评分和问题列表。  
**异常**：部分列无法计算时返回部分成功，并明确失败列。  
**后置条件**：诊断结果绑定到输入版本，不修改数据。

### UC-05 规整与清洗

**主流程**：选择时间规整策略 → 选择异常检测和替换策略 → 预览影响 → 确认执行 → 创建新数据版本和审计记录。  
**关键规则**：长缺失段默认不插值；原始数据不可覆盖；每个改动记录原值、处理值和原因。  
**异常**：处理后有效样本不足时版本标记为 `INVALID_FOR_MODELING`。

### UC-06 动态区间优选

**主流程**：选择窗口和阈值 → 计算输入/输出变化、SNR、响应关联和惩罚项 → 合并相邻区间 → 展示总分和分项 → 用户启用/禁用 → 创建区间集合。  
**异常**：没有合格区间时返回诊断建议，不自动降低阈值冒充成功。  
**后置条件**：区间集合可作为后续分析的掩码，原数据时间轴保持不变。

### UC-07 时滞分析

**主流程**：训练集标准化和去趋势 → 每个输入计算候选互相关峰 → 构造候选 `nk` → 在验证集比较 ARX 指标 → 选择最终时滞 → 生成补偿版本。  
**关键规则**：互相关峰只能产生候选，最终时滞必须经验证集复核。  
**异常**：候选差异不显著时输出不确定性并请求用户确认。

### UC-08 共线性分析与变量确认

**主流程**：计算 Pearson、Spearman、VIF、条件数 → 形成高相关组 → 结合验证集指标生成保留/删除建议 → 用户确认 → 创建变量集合。  
**关键规则**：删除变量属于高影响操作，Agent 不得无确认直接执行正式版本。  
**异常**：矩阵奇异时使用稳定求解或给出无法计算提示。

### UC-09 ARX 训练与评价

**主流程**：选择版本、区间和变量集合 → 配置 `na/nb/nk` 与估计器 → 按时间分区构造回归矩阵 → 训练 → 验证 → 保存参数、预测、指标和残差。  
**异常**：阶次过高、秩不足、数值不稳定、有效样本不足时模型失败，不写入正式模型版本。  
**后置条件**：测试集指标仅在最终模型冻结后计算。

### UC-10 闭环自动寻优

**主流程**：选择搜索空间和预算 → 创建 Study → 每个 Trial 生成中间版本并训练/验证 → 计算综合目标 → 保存成功与失败 Trial → 选择最佳方案 → 最终测试。  
**异常**：单 Trial 失败不终止 Study；全部失败时返回根因汇总。  
**关键规则**：目标函数不得读取测试集。

### UC-11 Agent 工作流

**主流程**：用户输入自然语言 → Planner 生成 JSON → Validator 校验工具、顺序、参数和权限 → 用户确认高影响步骤 → Executor 调用真实工具 → Controller 根据结果继续或停止 → 生成结论。  
**异常**：LLM 输出不可修复、工具不支持、参数越界、执行失败、LLM 不可用。  
**后置条件**：保存原始指令、原始模型输出、修复记录、最终计划、工具输入输出和停止原因。

### UC-12 报告与导出

**主流程**：选择运行 → 校验全部引用对象 → 生成图表、HTML/PDF、模型 JSON、流水线 JSON 和优选 CSV → 打包下载。  
**异常**：报告生成失败不回滚模型或数据版本；可单独重试。  
**关键规则**：报告中的每个核心数字必须引用真实记录。

### UC-13 数据血缘与运行记录

**主流程**：选择数据版本或模型 → 查看父版本、处理步骤、参数、耗时、代码版本和产物 → 跳转关联任务。  
**后置条件**：评委能够沿“原始数据 → 处理版本 → 模型 → 报告”复核。

### UC-14 取消与恢复

**主流程**：用户请求取消 → Worker 在安全检查点停止 → 已完成稳定产物保留 → 任务标记取消 → 用户可基于最近稳定版本重试。  
**异常**：不可中断的原子步骤完成后再取消，并在 UI 明确状态。

## 4. 人工确认点

以下步骤必须出现明确确认：

- 删除数据集或物理清理文件；
- 接受大规模异常值替换；
- 删除输入变量；
- 启动高预算闭环寻优；
- 采用不确定时滞；
- 将候选方案设为正式最佳方案；
- 导出可能包含敏感工业数据的包。
