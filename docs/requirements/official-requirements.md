# A14 官方需求拆解

文档状态：阶段 0 候选冻结版  
适用项目：IndusOpt 工模智优  
来源：2026“数字马力杯”第十三届浙江省大学生服务外包创新应用大赛赛题手册，A14 章节（手册页 54-59）及 A 类企业命题初赛评分标准（手册页 137）。

## 1. 命题核心

A14 要求构建一个面向流程工业系统辨识的数据智能优选与闭环寻优系统。系统需要把工业时序数据预处理、动态数据筛选、时滞与共线性处理、系统辨识、参数寻优、Agent 编排、报告生成和数据导出连接成可执行闭环。

官方业务闭环可归纳为：

```text
用户自然语言需求
→ Agent 解析并生成结构化工作流
→ 调度可信工业算法
→ 完成规整、清洗、动态区间筛选、时滞与共线性处理
→ 执行系统辨识与模型评价
→ 评价指标反馈到前置处理参数
→ 自动迭代寻优
→ 生成工程报告并导出优选数据集
```

## 3. 官方技术方向

官方要求或建议形成以下分层：

1. **Agent 层**：接入 DeepSeek、ChatGLM、LLaMA 等大模型，准确识别意图并拆解为结构化工作流。
2. **工业算法层**：使用 Python 封装清洗、对齐、动态截取、时滞、降维、系统辨识等算法，提供标准参数接口。
3. **流水线与反馈层**：执行工作流，捕获辨识评价指标，自动循环调参。
4. **解释与报告层**：把最优参数、指标和图表传入报告生成模块，形成工程解释。
5. **交互层**：提供 Web 界面、对话框、文件管理和可视化区域。

官方列出的库、框架和运行方式属于可选技术路线，不构成对 LangChain、LangGraph、特定前端或特定沙箱的强制绑定。

## 7. 明确不把以下内容误写为官方要求

以下内容是本项目的范围控制，不是赛题原文强制项：

- 仅做 MISO，不做完整 MIMO；
- 仅做离散时间 ARX，不做深度学习辨识；
- 使用 FastAPI、Vue 3、PostgreSQL、Redis、Optuna；
- 固定的指标定义、文件大小限制和默认参数；
- 单租户、本地工作区模式；
- 具体页面数量与 UI 风格。

## 8. 官方需求验收总表

阶段 11 前必须逐项提供可运行证据：

- [ ] CSV 和仿真数据真实进入后端数据链路。
- [ ] 清洗、区间、时滞、共线性、ARX 均为真实算法输出。
- [ ] 闭环优化真实执行多个 Trial，不是动画或预设结果。
- [ ] Agent 只编排工具，不直接编造指标。
- [ ] 报告中的数字可以回溯到数据库记录和算法输出。
- [ ] 导出的数据集与最优参数、数据版本一致。
- [ ] 演示覆盖“输入需求 → 自动执行 → 指标反馈 → 寻优 → 报告与导出”。
