# IndusOpt 工模智优 - 前端用户角色与场景分析

**文档版本**：`v0.1.0`  
**适用阶段**：阶段 0（需求与设计冻结）  
**责任角色**：Gemini (前端与可视化架构师)  

---

## 1. 角色概述

本项目针对流程工业系统辨识领域的工业建模痛点，服务于以下三类核心用户角色：

```text
+-----------------------------------------------------------------+
|                        IndusOpt 用户角色体系                      |
+-----------------------------------------------------------------+
|  [主角色] 工业建模工程师 (Modeling Engineer)                      |
|  - 驱动数据清洗、动态区间筛选、时滞补偿、共线性剔除与闭环寻优           |
|                                                                 |
|  [只读角色] 竞赛评审 / 专家观察者 (Reviewer / Observer)            |
|  - 审核算法证据、验证闭环效果、审查数据血缘与下载工程报告             |
|                                                                 |
|  [管理角色] 系统管理员 (System Admin)                            |
|  - 配置 LLM API Key、存储与文件限制、日志监控 (MVP 单机极简)         |
+-----------------------------------------------------------------+
```

## 2. 详细角色定义

### 2.1 工业建模工程师 (Modeling Engineer) — **P0 核心用户**

* **角色背景**：具备流程工业背景（如化工、冶金、电力、电力系统或自动化控制），熟知过程变量 (Input) 与控制目标 (Output)，但痛于繁重的工业数据预处理与人工试错。
* **核心目标**：
  1. 通过自然语言或直观配置，快速从嘈杂、长稳态的工业 CSV 中提炼出高动态、高信噪比的建模数据。
  2. 自动求得最优输入输出时滞与无共线性变量集合。
  3. 获得高拟合度 ($R^2$ / FIT) 的 ARX 系统辨识模型，并能通过闭环自动寻优参数。
* **UI/UX 诉求**：
  * **高信息密度与可视化**：能够清晰查看多变量时序对比、异常点高亮、动态区间排名与时滞 correlation 曲线。
  * **显式算法证据**：每步处理（如清洗、截取、剔除）需显示“前/后对比”与“算法理由”，拒绝黑盒。
  * **无缝交互闭环**：既可通过对话由 Agent 自动编排，也可在独立工具页面中进行手动微调与二次触发。
* **核心使用场景**：
  * **场景 A**：直接上传现场收集的原始 MISO 工业 CSV，进行质量诊断与交互式清洗。
  * **场景 B**：使用内置仿真工具生成含时滞/共线性/噪点的 S3/S4 数据，作为基线验证系统能力。
  * **场景 C**：在 Agent 对话框输入：“对数据集 S3 提取高信噪比动态段并完成闭环寻优，目标 FIT > 80%”，观察 Agent 逐级调度与参数迭代。

---

### 2.2 竞赛评审 / 专家观察者 (Reviewer / Observer) — **P1 演示角色**

* **角色背景**：外包大赛评审专家、企业工业算法主管、第三方审核员。
* **核心目标**：
  1. 快速验证系统是否真正由闭环算法驱动（而非前端硬编码假数据或假动画）。
  2. 审查 Agent 调度的工具链逻辑与参数迭代轨迹。
  3. 导出包含完整证据链的工程报告 (PDF/Markdown) 与优选数据集 (CSV)。
* **UI/UX 诉求**：
  * **一键演示与路径导航**：提供清晰的引导式演示流程（从仿真生成到闭环寻优与报告导出）。
  * **数据血缘可视化 (Data Lineage)**：显示数据版本 DAG 节点（`V0 原图 -> V1 清洗 -> V2 区间 -> V3 时滞补偿 -> V4 剔除共线性`），证明每步可追溯。
  * **收敛过程展示**：Optuna Trial 拟合度收敛曲线、参数重要性图。
* **核心使用场景**：
  * 点击“演示路径”按钮，加载预设仿真方案，在 3 分钟内完整走完数据诊断、清洗、区间选优、ARX 辨识、Optuna 闭环寻优至报告生成的全过程。

---

### 2.3 系统管理员 (System Admin) — **P1 辅助角色**

* **角色背景**：负责部署 Docker Compose 环境的运维或开发者本人。
* **核心目标**：
  1. 配置大模型 API Token (DeepSeek / 阿里通义千问)。
  2. 管理上传文件大小限制、数据目录清理与系统运行日志。
* **UI/UX 诉求**：
  * 极简设置表单、API Key 联通测试按钮、系统健康度仪表盘。
* **说明**：在 MVP (阶段 0-11) 中采用本地单机/单租户免登录模式，管理员界面为次要功能，不增加复杂的rbac权限拦截。

## 3. 用户痛点与前端设计映射表

| 传统工业建模痛点 | IndusOpt 前端解决方案 | 对应 UI 模块 |
|---|---|---|
| 工业数据长年处于稳态，动态响应少且难以人工挑选 | 动态区间算法可视化背景高亮 + 分阶段评分列表 | 动态区间优选 View |
| 无法确定过程变量存在多少步的时滞 | correlation 滞后曲线图 + 交互式候选滞后对比 | 时滞分析 View |
| 多输入变量间严重共线性导致辨识矩阵求逆发散 | 交互式 Pearson 热力图 + VIF 诊断条形图 + 变量剔除/保留切换 | 共线性与变量筛选 View |
| 预处理参数（如滤波窗长、动态阈值）与最终辨识指标脱节 | 闭环寻优收敛轨迹图 + 预处理参数 vs 辨识 FIT 联动分析 | 闭环寻优 View |
| LLM 幻觉生成不可信代码或假指标 | 白名单工具 DAG 过程追踪 + 算法原声 Response 证据面板 | Agent 智能工作台 |
