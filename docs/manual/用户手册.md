## 1. 这个软件解决什么问题

工厂历史库里有几年的数据，但能用来辨识模型的只有其中很小一部分。装置绝大多数时间运行在
稳态：输入不动，输出也不动。这样的数据行数再多，也不会告诉模型"输入变化多少、输出会跟着
变多少"。真正有价值的是那些短暂的动态片段——一次阀位调整、一次负荷升降、一次工况切换。

传统做法是靠工程师翻趋势图人工圈选，或者用一个"数据质量评分"排序取前 K 段。本软件的做法
不同：**它计算每个候选片段能给模型参数带来多少信息量，并且知道两个片段是否在讲同一件事。**

这句话的实际后果，可以在软件自带的「一键自评测基准」里当场验证：

- 在激励均匀的数据上（每次扰动同时动所有输入），本软件与传统评分法几乎没有差别；
- 在激励不均匀的数据上（操作员这段时间调这个阀、另一段时间调那个阀——**这才是真实历史数据的常态**），
  传统评分法会把预算全花在幅度最大的那个变量上，导致其余变量的增益被估成接近零，
  设计矩阵秩亏；本软件用 14% 的数据达到了全量数据的辨识精度。

**这不是"永远更好"，是"不会崩"。** 软件在报告里同时展示对自己不利的对照结果，
第 5 节说明如何阅读这些数字。

## 2. 安装与启动

### 2.1 推荐方式：Docker Compose（离线部署）

```bash
docker compose build
docker compose up
```

启动后：

| 服务 | 地址 |
|---|---|
| 后端 API 文档 | http://localhost:18000/docs |
| 前端界面 | 按 `frontend` 的部署方式访问（开发态默认 http://localhost:5173） |

栈内含 PostgreSQL 16、Redis 7、后端 API 与一个 RQ Worker。**全部本地运行，不需要外网。**

### 2.2 开发方式

```bash
# 后端
cd backend
pip install -e ".[dev]"
PYTHONPATH=. uvicorn app.main:app --reload --port 18000

# 前端（另开一个终端）
cd frontend
npm ci && npm run dev
```

前端开发服务器已配置 `/api/v1` 代理到 `http://127.0.0.1:18000`，需要改指向时设置
`VITE_API_TARGET`。

### 2.3 长任务后台执行（可选）

一次 120 试验的闭环寻优是分钟级的。要让接口立即返回、后台执行：

```bash
export INDUSOPT_BACKGROUND_OPTIMIZATION=true
PYTHONPATH=. rq worker indusopt --url redis://localhost:6379/0
```

**默认关闭。** 单机部署如果没有起 Worker，一个被排进队列却永远无人执行的任务，
比一个多等几分钟的请求更糟。Redis 或 Worker 不可用时软件会自动改为同步执行，
并在返回消息里说明走的是哪条路径。

## 3. 五分钟上手：一句话跑通全流程

1. 打开「Agent 工作台」；
2. 在输入框里写下你的目标，例如：

   > 提取 1 号塔高信噪比的动态数据，处理共线性后，通过闭环寻优找出最佳模型数据

3. 填入要处理的数据版本 ID（留空则只生成计划、不执行）；
4. 点击「提交给 Agent」。

系统会依次给出：

| 区块 | 内容 | 为什么要看 |
|---|---|---|
| 合规证明 | 每一项静态校验的通过情况、签名、代码版本 | 计划在执行前被机器检查过：只调用白名单内的工具、执行图无环、时序合法、高影响操作未经确认不会执行 |
| Agent 编排计划 | 每一步的工具、参数、状态 | 你可以逐步核对它到底打算做什么 |
| 工具真实输出 | 每一步算法的实际返回值 | 这些是算出来的，不是模型写的 |
| 结论与假设 | 一句话结论 + 系统替你做的假设 + 停止条件 | **假设栏最重要**：它列出所有你没说、系统替你定的事 |

> **计划来源标签**：标签会显示「大模型编排」或「确定性规则编排」。未配置大模型时是后者，
> 功能完整，不是降级状态。若大模型给出的计划没通过校验，系统会回退到规则编排并说明原因。

## 4. 完整流程分步说明

也可以不走 Agent，在左侧导航里逐页手动执行。各页对应关系如下。

### 4.1 仿真生成器（可选，用于验证）

没有现场数据时，用它生成带精确真值的测试数据。六个场景：

| 场景 | 特征 | 用途 |
|---|---|---|
| S1 | 基础单输入、无噪声 | 验证辨识链路本身是否正确（应当接近完美复现） |
| S2 | 多输入、不同滞后 | 验证时滞估计 |
| S3 | 长稳态 + 短动态 | 最接近常规辨识试验的数据 |
| S4 | 强噪声与异常污染 | 验证清洗与门控 |
| S5 | 高共线性输入 | 验证共线性诊断 |
| **S6** | **异构激励**：大幅动作集中在少数变量上 | **最接近真实历史数据**，也是暴露传统选段方法失效的场景 |

生成后会得到数据集 ID 与初始版本 ID，后续每一页都用**版本 ID**。

### 4.2 数据资产 Hub

上传现场 CSV（≤100 MiB，自动识别 UTF-8/GBK/GB2312 与逗号/分号/Tab）。上传后可以：

- 查看质量 Profile：缺失率、连续缺失、重复时间戳、采样周期直方图、冻结段、异常点、统计量与评分；
- 配置列角色：哪些是输入、哪个是输出、哪个是时间戳。

**原始数据永不覆盖。** 每次处理都派生一个新版本，形成可追溯的版本血缘图。

### 4.3 时间规整与清洗

统一采样周期、处理缺失与异常、去除重复时间戳。执行后派生新版本。

> 冻结段和长缺失段**不会**被无条件插值，正常阶跃**不会**被当作尖峰批量删除——
> 这两种"清洗"会直接破坏辨识所需的动态信息。

### 4.4 动态区间优选（核心功能）

页面参数：

| 参数 | 含义 | 建议 |
|---|---|---|
| 窗口长度 | 候选片段的样本数 | 取被辨识过程主时间常数的 2–5 倍 |
| 保留区间数 | 预算，最终保留几段 | 见下方提示 |
| 最低 SNR / 最大缺失率 / 最大异常率 | 质量门控阈值 | 先用默认值跑一次，看门控剔除统计再调 |

执行顺序是**先门控、后信息准则**：不合格的窗口在参与信息量比较之前就被剔除，
避免一段"信息量很大"的尖峰污染被选进来。

结果区给出：候选窗口数、通过门控数、最终选中数、采样占比、信息保留率、设计矩阵条件数、
CELF 求值加速倍数、停止原因，以及每一段的信息增益（单位：bit——这是"这段数据教了模型多少"
的物理量，不是一个无量纲评分）。

> ⚠️ **预算提示**：如果选出的窗口少于 3 个，页面会出现橙色警告。实测表明窗口数太少时，
> 即使信息准则也覆盖不了全部参数方向，设计矩阵仍可能秩亏。此时应**增大样本预算或缩短窗口长度**
> 后重跑。这是提示不是阻断——有时两个窗口确实就是这段记录的全部。

### 4.5 多变量时滞分析

对每个输入估计纯滞后。采用预白化互相关：先对输入拟合 AR 模型、用它同时滤波输入与输出，
再做互相关。

**为什么不能直接做互相关**：输出的强自相关会在原始互相关函数上制造又宽又偏的伪峰，
而且这个偏差是系统性的（原始互相关等于真实脉冲响应与输入自协方差的卷积）。

候选峰会再用验证集自由仿真复核一遍，避免单看相关系数选错。

### 4.6 共线性与变量筛选

给出 Pearson、Spearman 相关矩阵、方差膨胀因子 VIF、标准化设计矩阵的条件数，
并把高度相关的变量分组。

**软件不会替你删变量。** 它给出诊断和分组，由你决定保留哪一个——因为哪个变量在现场可调、
哪个只是伴随现象，是工艺知识，不是数据能回答的问题。

### 4.7 系统辨识（ARX）

选择阶次 `na`、`nb`、时滞 `nk`，执行辨识。可以施加**先验约束**：

| 约束 | 例子 |
|---|---|
| 增益符号 | 「加大蒸汽流量，塔顶温度必然上升」→ u1 增益为正 |
| 增益区间 | 「这个通道的增益不可能超过 2」 |
| 时滞下界 | 「管线传输至少 6 个采样周期」 |
| 稳定性 | 要求 `A(q)` 全部极点在单位圆内 |

先验是**硬约束**：不满足就拒绝入库，并给出 `PRIOR_CONSTRAINT_VIOLATED`。每条先验都会
被记录来源并出现在报告中——先验是可追溯的工程输入，不是隐藏的调参手段。

### 4.8 闭环寻优

自动搜索预处理参数与模型结构的组合。

**目标函数是验证集自由仿真 FIT**，不是一步预测 FIT。原因见第 5.1 节。

搜索采用分级设计：采样器探索昂贵的门控与优选参数，每个试验在一次优选结果上扫描完整的
模型结构网格。实测昂贵环节被摊薄 24 倍。

系统还会做**历史策略热启动**：如果记忆库里有数据画像相近的历史寻优结果，会把那次的最优
参数作为本次的起始试验。同一个数据集**不会**用自己的历史热启动（那是自欺）。

失败与被剪枝的试验一律保留展示，不隐藏。

### 4.9 一键自评测基准

点一次按钮，系统用带真值的仿真基准当场重算自己的全部技术主张：数据优选消融、
指标区分度、时滞估计对照。**表里每个数字都是这次请求算出来的**，没有缓存也没有写死。
主张一旦不成立，表格会立刻显示出来。

### 4.10 报告与交付中心

- **生成图文报告**：报告里的每一个数字都绑定到真实运行记录。语言模型负责撰写文字结论，
  但**一个数字都不许写**——它只能输出占位符，由渲染器绑定实际数值。含未绑定数字的草稿
  会被拒绝并要求重写，连续三次不合规则回退到模板化结论。
- **导出优选数据集**：把优选后的数据导出为 CSV，附带完整血缘元数据。

## 5. 读懂系统给出的判断

### 5.1 为什么主指标是"自由仿真 FIT"而不是"一步预测 FIT"

- **一步预测**：预测下一时刻时，用的是**实测**的上一时刻输出。
- **自由仿真**：只有起始几个点用实测输出热启动，之后完全用模型自己的预测往前推。

多数工业过程的输出是强自相关的，模型只要"抄上一时刻"就能拿到很高的一步预测分数，
输入通道估错几乎不受惩罚。实测数据：在 S6 场景上，一个参数误差 15%、稳态增益完全错误、
设计矩阵秩亏的模型，一步预测 FIT 仍有 96.5，只比最优模型低 0.5 分。同一组模型的
自由仿真 FIT 跨度是 15.3 分——**区分度差 28.5 倍**。

用于控制的模型必须能在没有实测输出反馈的情况下往前推，所以自由仿真才是对的口径。

一步预测 FIT 仍然保留为**诊断量**：两者的差值 `fit_gap` 越大，说明模型越是在靠输出自相关
"抄答案"，这是过拟合的直接信号。

### 5.2 条件数与秩状态

- **条件数**：设计矩阵最大奇异值与最小奇异值之比。越大说明参数估计对噪声越敏感。
- **秩亏**：某些参数方向在数据里根本没有被激励，对应参数无法辨识。此时无论算法多好，
  估计值都没有意义。

看到「秩亏」标签，正确的反应是**回去补数据或补激励试验**，而不是换个算法再试。

### 5.3 持续激励阶次

系统会在辨识结果里告诉你「该数据段仅满足 2 阶持续激励，不足以辨识 na=2、nb=2 的模型（需 4 阶）」，
字段是 `validation.excitation_shortfall`。

**这是诊断，不阻断建模。** 曾经把它做成阻断，实测发现它两个方向都会判错：一个 8 电平输入
被报成 1 阶（远低于要求），而它的模型自由仿真 FIT 有 95.8%；放松容差后，一个 3 电平输入
达标了，而它的模型自由仿真 FIT 只有 0.2%。没有任何容差能把两者分开，所以拿它当门槛会
既拦掉好模型又放过坏模型（`ALG-0.2` §3 有完整数据）。

**真正会阻断的是设计矩阵秩亏。** 看到激励不足的提示时，正确的反应是把它和自由仿真 FIT、
秩状态放在一起看，而不是单独据此下结论。

### 5.4 信息增益（bit）

每段数据的信息增益以 bit 为单位给出，含义是"这段数据把参数的不确定性缩小了多少"。
增益随选段递减是必然的（后选的段与已选段有重叠信息），若你看到某段增益接近 0，
说明它没有带来任何新东西，可以不要。

## 6. 接入大模型（可选）

系统支持任何 **OpenAI 兼容**的 chat/completions 端点，覆盖 DeepSeek、Ollama、vLLM、
Xinference 以及自建 ChatGLM / LLaMA：

```bash
export INDUSOPT_LLM_PROVIDER=ollama
export INDUSOPT_LLM_BASE_URL=http://localhost:11434/v1
export INDUSOPT_LLM_MODEL=qwen2.5:7b
# 云端服务另加 INDUSOPT_LLM_API_KEY
```

**未配置时系统完整可用**，这是刻意的：现场可能没有网络。

大模型在本系统里负责*提议*，不负责*授权*：

- 它生成的计划要通过与规则计划**完全相同**的白名单、执行图与合规校验，不通过即回退；
- `requires_confirmation` 一律取自白名单而非模型输出，模型无法借此解锁未经确认的导出；
- 它撰写报告结论时一个数字都不许写。

因此模型不可用、输出畸形、甚至刻意越权，最坏结果都只是"回退 + 说明"，不会产生错误的产物。

## 7. 常见问题与错误码

| 现象 | 错误码 | 原因与处理 |
|---|---|---|
| 优选返回"没有找到动态区间" | `NO_DYNAMIC_SEGMENT_FOUND` | 全部候选窗口被门控剔除。放宽最低 SNR / 最大缺失率 / 最大异常率，或换一段含动态的数据 |
| 辨识被拒绝：设计矩阵秩亏 | `DESIGN_MATRIX_RANK_DEFICIENT` | 输入之间近似线性相关，OLS 无法分离各自贡献。先做共线性分析删掉冗余变量，或改用 Ridge |
| 训练样本不足 | `INSUFFICIENT_ROWS` | 选中的训练行数不足参数个数的两倍。放宽优选预算或缩短窗口 |
| 模型不入库 | `MODEL_UNSTABLE` | `A(q)` 有极点在单位圆外。降低 `na`、增大正则或检查数据 |
| 先验冲突 | `PRIOR_CONSTRAINT_VIOLATED` | 辨识结果违反你给的增益符号/区间。要么数据有问题，要么先验需要复核——两者都值得查 |
| 找不到数据版本 | `DATASET_VERSION_NOT_FOUND` | 版本 ID 填错，或用成了数据集 ID。版本 ID 在数据资产 Hub 的版本图里 |
| 上传被拒：文件过大 | `DATASET_FILE_TOO_LARGE` | 超过 100 MiB。请先按时间切分 |
| 上传被拒：格式不符 | `DATASET_FILE_TYPE_INVALID` / `DATASET_MIME_TYPE_INVALID` | 扩展名或 MIME 类型不是 CSV |
| 编码识别失败 | `CSV_ENCODING_UNSUPPORTED` | 非 UTF-8 / GBK / GB2312。请另存为 UTF-8 后重传 |
| 时间列解析失败 | `TIMESTAMP_PARSE_FAILED` | 时间戳格式无法识别。检查列角色配置是否指对了时间列 |
| 参数越界 | `PARAMETER_OUT_OF_RANGE` | 请求参数超出允许范围，`details` 里给出了具体字段与边界 |
| 寻优任务查不到 | `OPTIMIZATION_STUDY_NOT_FOUND` | study_id 填错，或该任务不属于当前数据库 |
| 导出无内容 | `EXPORT_NO_SELECTION` | 尚未执行优选，没有可导出的选中数据 |
| 寻优返回后状态里没有试验 | — | 走的是后台执行路径，稍后再查。研究状态会从 `queued` 变为 `running` 再到 `succeeded` |
| 激励不足提示 | — | 不是错误码，是 `validation.excitation_shortfall` 字段（见 5.3 节），不阻断建模 |

完整错误码见 [`docs/api/error-codes.md`](../api/error-codes.md)。

## 8. 已知限制

诚实列出，避免在现场踩坑：

1. **模型类别限于离散时间 MISO ARX**。不支持多输出、连续时间、非线性与时变模型；
2. **全部算法验证基于仿真数据**。公开工业数据集上的外部验证尚未完成
   （原因见 `docs/experiments/` 各报告的"有效性威胁"章节）；
3. **D-最优优选不是永远最优**。在激励均匀且数据干净的场景下，传统加权评分法可能略优
   （实测差距约 1 个百分点）；它的价值在于不会在异构激励下崩溃（实测差距 11 个百分点加秩亏）；
4. **预算太小时信息准则也救不了**。选出窗口少于 3 个时会给出警告，见 4.4 节；
