# 答辩 PPT

产物：[`../IndusOpt-A14-答辩.pptx`](../IndusOpt-A14-答辩.pptx)（11 页）
生成脚本：`build.js`

## 重新生成

```bash
cd docs/competition/slides
npm install pptxgenjs        # 仅首次
node build.js                # 在当前目录写出 IndusOpt-A14-答辩.pptx
```

内容改动请改脚本再重跑，不要直接在 PowerPoint 里改后覆盖——否则下次重跑会把修改冲掉。
唯一的例外是排版微调（见下文"尚未做的校对"）。

## 页面结构

| 页 | 内容 |
|---|---|
| 1 | 封面：一句话主张 + 三个关键数字 |
| 2 | 问题：有效样本被稳态淹没；现有两类做法 |
| 3 | **我们把「标准答案」实现了一遍，然后发现它不成立**（14.81% 对 14.82%） |
| 4 | 我们的做法：用信息量代替经验权重（含"不主张全局最优"） |
| 5 | 完整闭环：一句自然语言驱动全流程 |
| 6 | 我们没有照做的地方：模型评价口径（28.5×） |
| 7 | 可信性不是承诺，是机制 |
| 8 | **我们同时提交对自己不利的结果**（四条） |
| 9 | 结论不是单点巧合：200 个工作点 |
| 10 | 工程完成度 |
| 11 | 收尾：评委不需要相信 PPT，点一下按钮就能验证 |

每页都写了演讲备注（`addNotes`），在 PowerPoint 的备注栏可见。

## 讲的时候建议

第 3 页和第 8 页是这份材料区别于其他队伍的地方，不要略过。
第 11 页之后直接切到产品，现场点一次「一键自评测基准」——比任何一页 PPT 都有说服力。

## 已做的校验

| 项目 | 结果 |
|---|---|
| OOXML 结构与图表校验 | 通过（`validate.py`） |
| 内容完整性 / 占位符残留 | 通过，无 `lorem` / `TODO` / `xxx` |
| 元素越界 | 仅封面与尾页的装饰圆形有意出血，无文字或卡片越界 |
| 文字溢出估算 | 0 处风险（按 CJK 全角、半角 0.52 em 估算行数） |

## 尚未做的校对

**未做渲染后的视觉复核。** 本开发环境的 LibreOffice 不可用（连纯文本都无法转换），
因此无法把幻灯片渲染成图片逐页检查。上表的溢出估算是按字宽模型算的，不是看图看出来的。

字体指定为 `Microsoft YaHei`，在中文 Windows 版 PowerPoint 上正常；
若在其他环境打开出现字体回退，行宽会变化，需重新检查是否有文字换行超框。

**请务必在 PowerPoint 里打开过一遍再用于答辩。**
