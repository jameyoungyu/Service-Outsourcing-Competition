# 实验报告：窗口长度与样本预算敏感性扫描

编号：`EXP-3.0`
日期：2026-08-08
执行器：`backend/scripts/sweep_selection_sensitivity.py`
原始数据：`docs/experiments/sensitivity-sweep.json`

---

## 1. 实验目的

`EXP-1.1` §7 第 4 条把这件事列为**该报告最主要的遗留威胁**，原话是：所有结论都建立在 `window_size=60`、预算 12 个窗口这一组取值上。

只在一个工作点上获胜的方法不是方法，是巧合。本实验在两个轴上扫描，回答两个问题：

1. `EXP-1.1` / `EXP-2.1` 的结论在多大范围的窗口长度与样本预算下成立？
2. **D-最优在什么条件下也会失败？** 这个边界必须找出来并写进产品，否则工程师会在不知情的情况下拿到一个秩亏的模型。

---

## 2. 实验设置

| 轴 | 取值 |
|---|---|
| 窗口长度 `window_size` | 30、60、90、120、180（步长固定为 `window_size/2`） |
| 样本预算（占训练区间比例） | 5%、10%、15%、25% |
| 场景 | S3（同构激励）、S6（异构激励） |
| 随机种子 | 5 组（`20260807` 起连续取值） |
| 策略 | `energy`、`weighted`、`ids` |

共 **200 个测量点**（5 窗长 × 4 预算 × 5 种子 × 2 场景），每点跑 3 种策略。

### 2.1 为什么预算按"行数"而不是"窗口数"给

这是本实验能成立的前提。在固定窗口数下，长度 30 的窗口和长度 180 的窗口买到的样本量差 6 倍；窗口之间还有重叠，去重后的行数又不一样。**只有把预算固定成行数，"同等预算、不同方法"才是一句真话。**

为此给 `select_by_energy` 与 `select_by_weighted_score` 补了 `budget_rows` 入口（`take_top_k`），三种策略共用同一套预算消耗逻辑，差别只在打分方式上。

### 2.2 预算是上限，不是目标

某个策略因为信息增益耗尽而提前停止时，按实际覆盖率记录，不补足到上限。那是被测行为本身，不是需要归一化掉的噪声。所以表中 `ids` 的覆盖率常略低于另外两者——它拿的样本更少。

---

| w180 / 25% | 77.95 (5) | 77.95 (5) | **89.71 (0)** |

**结论 1：`EXP-1.1` 的结论不是单点巧合。** 参数误差最优次数：`ids` 18 / 20，`energy` 2 / 20，`weighted` 0 / 20。满秩比例：`ids` 16 / 20，`weighted` 2 / 20，`energy` 1 / 20。

**结论 2：两种逐窗口打分法在异构激励下几乎全域失效。** 20 个工作点里它们只在 3 个点上摆脱秩亏，且全都出现在**最短窗口 + 最大预算**（w30/15%、w30/25%）。原因很直白：窗口越短、预算越大，选中的窗口个数越多，靠数量偶然覆盖到 u2/u3 的概率才上升。这是**撞上的**，不是**选出来的**。

**结论 3（对主口径不利，本实验的主要发现）：D-最优也有失效边界。** 4 个工作点上 `ids` 同样 5 / 5 次秩亏：w90/5%、w120/5%、w180/5%、w180/10%。

按"预算能装下几个窗口"（`budget_rows / window_size`）排列，边界非常干净：

| 工作点 | 预算/窗长 | `ids` 是否秩亏 |
|---|---:|---|
| w30 / 5% | 7.0 | 否 |
| w60 / 5% | 3.5 | 否 |
| w120 / 10% | 3.5 | 否 |
| w180 / 15% | 3.5 | 否 |
| **w90 / 5%** | **2.3** | **是** |
| **w180 / 10%** | **2.3** | **是** |
| **w120 / 5%** | **1.8** | **是** |
| **w180 / 5%** | **1.2** | **是** |

**分界落在 2.3 与 3.5 之间，没有交叉点。** 含义是清楚的，也不该被粉饰：当预算只够装下两三个窗口时，**无论怎么选都覆盖不了全部参数方向**（本模型 6 个参数）。这不是准则失灵，而是预算本身不足——信息准则能保证"在能选的范围内选最好的"，不能凭空造出数据里没有的激励。

### 3.1 这条边界已经写进产品

`SelectionResult.budget_advisory`（`MIN_WINDOWS_FOR_COVERAGE = 3`）：选出的窗口数少于 3 时，接口返回一条提示，前端在优选页以警告条展示，内容是"增大样本预算或缩短窗口长度后重跑"。

**刻意做成提示而非阻断。** 有时两个窗口就是这段记录的全部，直接拒绝会让工程师什么都拿不到。硬信号仍然是激励报告上的 `rank_deficient` 与 `excitation_satisfied`。由 `TestBudgetAdvisory` 三项测试锁定，其中一项专门断言提示不会阻断结果返回。

## 4. 结果：S3 同构激励

| 窗长/预算 | energy | weighted | ids |
|---|---|---|---|
| w30 / 5% | 95.37 | 93.23 | **95.58** |
| w60 / 5% | 87.21 | 91.11 | **95.42** |
| w90 / 5% | 84.50 | **94.13** | 93.54 |
| w120 / 5% | 80.99 | **88.65** | 81.71 |
| w180 / 5% | **84.50** | 80.63 | **84.50** |
| w180 / 10% | 87.62 | 94.18 | **94.96** |
| 其余 14 个工作点 | 94.3–95.6 | 94.2–95.6 | 94.9–95.6 |

**结论 4：同构激励下 20 个工作点全部满秩，无任何策略崩溃。** 参数误差最优次数 `energy` 10、`ids` 7、`weighted` 3，但跨度只有 1.5%–4.8%，且集中在 5% 这一档最紧的预算上；预算 ≥10% 后三者基本无法区分（自由仿真 FIT 全部落在 94.3–95.6）。

这与 `EXP-1.1` §4 的结论一致，并把它推广到了 20 个工作点：**同构激励下"选哪些"不重要**。此前只在单点上观察到这一现象，现在可以说它在整个参数范围内成立。

**结论 5（不利结果）：S3 上 `energy` 的最优次数最多（10 / 20）。** 主口径 `ids` 只有 7 次。差距很小且在种子波动内（`EXP-1.1` 实测 S3 上参数误差的种子间标准差为 ±0.51%，而此处策略间跨度多在 0.3% 以内），但次数就是次数，照写。

## 5. 汇总：结论的适用范围

| 主张 | 成立范围 | 不成立的地方 |
|---|---|---|
| D-最优在异构激励下显著优于逐窗口打分 | 20 个工作点中 16 个（预算/窗长 ≥ 3.5 时全部成立） | 预算/窗长 ≤ 2.3 时三者一起秩亏 |
| 逐窗口打分在异构激励下失效 | 20 个工作点中 17–19 个 | 最短窗口 + 大预算（w30/15%、w30/25%）时靠数量撞上 |
| 同构激励下策略选择不重要 | 全部 20 个工作点 | — |
| 完整加权分不优于纯能量法 | S3、S6 各 20 个工作点均成立 | — |

## 6. 有效性威胁

1. **仍是仿真数据**：与 `EXP-1.1`、`EXP-2.1` 同一威胁，结论只在线性 ARX 假设下成立。
2. **步长绑定为 `window_size/2`**：未单独扫描步长。步长影响候选窗口的重叠程度，进而影响同一行预算下能选到的窗口个数，可能移动第 3 节那条边界的位置。
3. **模型结构取真值**：`na/nb/nk` 已知。§3 那条"6 个参数需要至少 3 个窗口"的边界与参数个数直接相关，换结构后阈值会变；`MIN_WINDOWS_FOR_COVERAGE = 3` 因此是一个保守的经验常数，不是从参数个数推导出的公式。
4. **5 组种子**：秩亏次数一栏出现的都是 0 或 5（除 w30/15% 的 4 与 w60/25% 的 4），说明这些是确定性失效模式而非随机波动；但 5 组种子不足以给出置信区间。
5. **只扫了两个轴**：`ridge`、`min_information_gain_bits` 未扫描。
